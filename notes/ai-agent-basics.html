學習筆記 04 ／ 工具與行動

AI Agent 入門

從安排讀書時間的例子，理解 AI 如何使用工具、觀察結果，再決定下一步。

學習目標

  • 知道 AI Agent 的基本概念。
  • 能分辨固定工作流程與依結果調整行動的方式。
  • 理解工具、停止條件與人工確認的作用。

核心概念

AI Agent（人工智慧代理）的用法不完全一致。本篇以大型語言模型為核心的 Agent 為例：系統接收目標後，由模型依目前資訊決定下一步，必要時使用工具，再根據結果繼續處理。

大型語言模型（LLM）是能理解與生成文字的模型；工具則是系統提供的功能，例如查詢行事曆或計算時間。模型提出工具呼叫後，需要程式實際執行，再把結果交回模型。

確認目標 → 選擇行動 → 取得結果 → 決定繼續、詢問或結束

工作流程（Workflow）通常由程式預先安排步驟。例如固定執行「初稿、檢查、修正」，屬於明確的流程；Agent 則更強調由模型依結果調整接下來的行動。不是呼叫模型三次，就一定成為自主 Agent。

設計時也要定義完成條件與停止條件，例如找到可行時段就結束，連續查詢三次仍無結果就詢問使用者，避免無限嘗試。

具體例子

以下是虛構的「讀書排程助手」示範，假設系統已取得查詢行事曆的權限：

請找出明天下午兩段各 30 分鐘、不與既有行程衝突的讀書時間。先給我建議，等我確認再加入行事曆。
  1. 查詢：Agent 呼叫行事曆工具，取得明天下午的行程。
  2. 觀察：工具回傳只有 14:00～14:30 空閒，其餘時間已排滿。
  3. 調整：因為不夠兩段，Agent 詢問：「可以把第二段改到晚上嗎？」而不是假裝已找到。
  4. 繼續：使用者同意後，Agent 才查詢晚上的空檔，提出兩段時間。
  5. 確認與結束：使用者確認後才呼叫新增行程工具；依工具回傳結果說明哪些行程已建立，若失敗就說明失敗，不能只憑模型文字宣稱完成。

這是概念示範，不是實際使用成果；本筆記網站沒有連接行事曆或模型 API（讓程式呼叫模型的介面）。

常見誤解

只要會聊天，就是 Agent？

聊天是互動方式。依本篇定義，還要看系統是否會依目標與執行結果決定後續行動。

一定要多個模型一起合作？

不一定。單一模型配合工具，也能構成 Agent；是否分成多個角色要看任務需要。

有工具就能做任何事？

不能。工具必須由系統提供，且受權限限制。像範例已要求先確認，Agent 就不能擅自建立行程；工具失敗也不代表任務完成。

Agent 一定比固定流程好？

不一定。步驟固定的任務可能用簡單流程就足夠；增加自主判斷也可能增加成本與出錯機會。

小練習與參考答案

讀書排程助手第一次查詢行事曆時，工具回傳「連線失敗」。它卻說「明天下午沒有行程，已安排兩段讀書時間」。這個回答有什麼問題？下一步應怎麼做？

查看參考答案

連線失敗表示沒有取得資料，不代表行事曆是空的，也沒有證據顯示行程已建立。助手應說明目前無法確認空檔，依設定有限次重試，或請使用者提供可用時間；取得資料、提出建議並獲得確認後，才可新增行程。

重點回顧

Agent 依目標選擇行動，觀察工具結果後再決定下一步。工具提供實際能力，但仍需明確權限、完成與停止條件，以及必要的人工確認。
